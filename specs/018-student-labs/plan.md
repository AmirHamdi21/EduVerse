# Implementation Plan: Student Labs Integration

**Branch**: `018-student-labs` | **Date**: 2026-04-11 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/018-student-labs/spec.md`

## Summary

Replace all mock/demo data in the student labs feature with live API data from the existing `LabService`. The current `LabsCubit` generates 8 hardcoded demo labs — it will be rewired to call `LabService.getAll(courseId)` with course selection from `EnrollmentService.getMyCourses()`. The existing `LabDetailsSheet` (bottom sheet) will be replaced with a **separate full screen** (`LabDetailScreen`) per spec clarification. A new submission bottom sheet (`LabSubmissionSheet`) will be added. All existing UI colors, structure, and component styles will be preserved (≥85% visual similarity). No mock data will remain in modified files.

## Technical Context

**Language/Version**: Dart 3.x with Flutter 3.x
**Primary Dependencies**: flutter_bloc (BLoC/Cubit), Dio (via CoreApiClient/LabService), webview_flutter (Google Drive preview), file_picker (file uploads), markdown package (instruction rendering)
**Storage**: shared_preferences (lightweight caching of lab list), path_provider (temp storage for file uploads)
**Testing**: flutter test (unit tests for Cubits, widget tests for screens/sheets)
**Target Platform**: iOS/Android (Flutter mobile app)
**Project Type**: Mobile app feature module (student-facing)
**Performance Goals**: Labs list loads within 2s on 3G/4G; grade viewing within 1s; ≥95% submission success rate on first attempt
**Constraints**: ≥85% UI visual similarity mandatory; zero mock data in modified files; fully responsive (mobile/tablet/desktop); existing app theme/colors/layout preserved
**Scale/Scope**: 5 files modified, 7 new source files created, existing LabService reused (already has all endpoints from Phase 1)

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **I. BLoC State Management First** — `LabDetailCubit` will drive all API calls for lab detail; `LabsCubit` rewritten for labs list; no widget-level API calls
- [x] **II. Strict Data Layer Separation** — `LabModel` cleaned to match backend API JSON + website TypeScript `Lab` interface; `LabService` already extends `CoreApiClient` with Dio
- [x] **III. Type Safety & Error Handling** — `isLate` parsed as boolean (labs) not number (assignments); decimals via `double.tryParse(value.toString())`; `PaginatedResponse<T>` for paginated endpoints; safe enum parsing with `orElse` defaults
- [x] **IV. Website Feature Parity** — Matches website `LabView` + `LabInstructions` + `SubmissionForm` component hierarchy; no Flutter-only orphan features added; student-only permissions enforced
- [x] **V. Testable Architecture** — `LabService` injectable into `LabDetailCubit` and `LabsCubit`; all BLoCs mockable; services testable with mocked Dio
- [x] **VI. Real-Time Communication Integrity** — N/A for labs (no WebSocket; REST-only feature)
- [x] **VII. Static Data Elimination** — `_generateDemoLabs()` will be removed from `LabsCubit`; all hardcoded lab lists in modified files replaced with API data; post-implementation audit planned
- [x] **VIII. Aggressive Clarification** — 3 questions asked and answered during `/speckit.clarify` (navigation pattern, submission form pattern, analytics scope)
- [x] **IX. Role-Based Access Control Enforcement** — Student-only scope: can submit labs and view own submissions; no create/edit/delete buttons visible; UI prevents unauthorized actions
- [x] **X. File Upload & Google Drive/YouTube Integration** — Lab submission via `POST /labs/{id}/submissions/upload` with FormData `file` field; Drive preview via WebView with iframe URL; client-side file validation before upload
- [x] **XI. Multi-Phase Plan Adherence** — Phase 4 of 10; depends on Phase 1 (LabService, LabModel); independent of Phases 5-9; follows integration plan structure
- [x] **XII. UI Consistency & Visual Preservation** — ≥85% similarity enforced; `LabCard` visual design preserved; new `LabDetailScreen` follows existing app color/theme patterns; mock data removal preserves UI space with empty states
